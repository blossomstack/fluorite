# Fluorite E2E Interoperability Tests

This directory contains end-to-end interoperability tests that verify serialization/deserialization compatibility between the Rust, TypeScript, Swift and Go code generated by Fluorite.

## Overview

The interoperability test ensures that:

1. **Rust -> TypeScript**: Rust can serialize data to JSON that TypeScript can correctly deserialize
2. **TypeScript -> Rust**: TypeScript can serialize data to JSON that Rust can correctly deserialize
3. **Rust <-> Swift** and **Rust <-> Go**: the same, for the other two backends
4. **Round-trip integrity**: Data survives round-trip serialization between languages

The Swift and Go legs are skipped when their toolchains are absent. The Go leg additionally
fails if `gofmt -l` reports anything under the generated package — generated Go is expected
to be byte-identical to gofmt output, and reformatting it here would hide a template bug.

## Test Scenarios

The tests cover the following schema types from `examples/demo/fluorite/`:

- **User object**: Complex struct with various field types including optional `Any` field
- **Enums**: `UserStatus`, `Gender`, `OrderStatus`, `AlertSeverity`, etc.
- **Tagged unions**: `UserEvent`, `OrderEvent`, `Message` with adjacently tagged format
- **Cross-package imports**: Types referencing types from other packages
- **Primitive union variants**: `Message::PlainText(String)`

## Running the Tests

### Using Make

```bash
make interop-test
```

### Direct Execution

```bash
./tests/interop/run-interop-test.sh
```

## Test Flow

1. **Build Phase**:
   - Build Rust demo binary
   - Build Fluorite CLI
   - Generate TypeScript types from `.fl` schemas
   - Compile TypeScript to JavaScript
   - Generate Go types, check them with `gofmt -l` and `go vet`, and build the Go demo

2. **Rust -> TypeScript Test**:
   - Rust demo writes sample JSON files
   - TypeScript demo reads and validates the JSON files

3. **TypeScript -> Rust Test**:
   - TypeScript demo writes sample JSON files
   - Rust demo reads and validates the JSON files

## Fixtures

The `fixtures/` directory contains JSON files generated during testing:

- `rust_to_ts/`: JSON files written by Rust, read by TypeScript
- `ts_to_rust/`: JSON files written by TypeScript, read by Rust
- `rust_to_swift/`, `swift_to_rust/`: the same pair for Swift
- `rust_to_go/`, `go_to_rust/`: the same pair for Go

These files are gitignored as they are generated during test execution.

## Adding New Test Cases

To add new interoperability test cases:

1. Update or add schemas in `examples/demo/fluorite/`
2. Add sample data creators in both:
   - `examples/demo/src/main.rs`
   - `examples/demo-ts/src/index.ts`
   - `examples/demo-go/main.go`
3. Update the file lists in every program
4. Regenerate types and run tests
